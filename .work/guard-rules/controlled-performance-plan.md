# 受控性能对比边界

范围：只测量并裁决事件机制，不修改生产行为。试验台架为明确的 spike，不安装常驻组件，不改变原安装配置、电源计划或任务。

- A/B 共用最终生产 Reader、PolicyEngine、Coordinator、Runner；A不投递前台信号，B投递；原周期15秒、轻路径1秒、完整评估5秒不缩短。
- 0/1/128项 × 静止/同准入切换/名单内外切换/快速切换，三组交替顺序。控制事实与信号用于消除桌面扰动；真实Reader执行成本、实际隔离status写入纳入测量，电源/亮度/供电副作用计数拦截。虚拟时间只用于矩阵的时间覆盖，CPU/分配量是真实进程测量。
- 额外做真实时间、相同周期相位的准入回放；这验证调度延迟，不是Windows事件投递时延。已有真实事件链证据单独引用，不混称。
- 真实监听静止A/B交替测量；有额外前台事件的轮次标记扰动，不计静止开销结论。真实Reader成本包含于各轮，并另做监听启停及普通线程回收对照，不宣称独立Reader微测完成。
- 2026-10-01补测调整：连续交替轮仍受前台通知扰动，保留为INVALID。最终采用三次独立A→B；B明确预留20秒稳定期，消化准备期标记并保存其计数，再完整计时30秒。计时期间仍要求零通知、监听健康；准备期不算成本样本。顺序/预热及周期相位不完全对齐，因此不以CPU差值或少一轮评估宣称改善。独立events-only诊断最多保存256条原生ID，不采窗口标题，不纳入成本测量。
- 保留条件：准入回放有可重复延迟收益；静止/同准入不增加完整业务工作；Reader、轮次、待处理工作有界；无持续句柄/线程增长。短时CPU/内存波动不外推长期稳定；既有Engine启动/20MB预算不由台架替代；整机能耗未测。
- 若结果不支持保留，记录裁决和后续最小变更范围，不在测量期间顺手重构。因真实静止环境无法控制或证据不足不能假称通过。

Owner仍为既有Coordinator/Listener/Runner；台架只拥有一次试验的有界状态和隔离产物。测试原安装不停止，读不到交互桌面即失败。平台消息循环依据：[SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)。
