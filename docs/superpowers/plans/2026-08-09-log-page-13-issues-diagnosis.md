## 3. 逐项根因与反证

### 3.1 问题 1：标题下说明文字间距

**根因：** 页面标题、卡片内边距和 `SettingsCardDescription` 的段落间距叠加，日志页没有专用的紧凑说明层级。相关位置为 `SmartGuard.Settings.xaml:98`、`:116`、`:789`、`:1275`、`:1287`。

**反证：** 这不是随机渲染错误；其他复用相同卡片样式的页面也采用相同基础间距。当前缺少针对日志页标题—说明—工具栏距离的真实窗口断言，因此不能只凭静态 XAML给出最终像素值。

**修复边界：** 仅为日志页说明文字增加局部样式/边距；不要全局修改 `SettingsCardDescription`。

### 3.2 问题 2：自动换行切页后失效

**已确认机制与待验证假设：** `SettingsLogPageHostWiring.WireLogTableWrapMode` 通过遍历当前可视树修改 `TextBlock.TextWrapping`，而 `LogTableCellTextStyle` 的默认值是 `NoWrap`。用户症状证明切页后新行没有稳定继承已勾选的换行状态；一种高概率假设是 `LoadingRow` 执行时单元格文本视觉树尚未完整生成，但当前证据尚未记录事件顺序和视觉树状态，不能把该时序直接写成已证实根因。

**反证：** 实现并非完全没有处理新行，它订阅了 `LoadingRow`；但 `LogPaginationWpfTests.Wrap_toggle_switches_between_fixed_and_bounded_auto_row_height` 只验证行高，没有创建真实单元格、替换 ItemsSource 或验证翻页后的文本换行。

**修复边界：** 将换行改为样式/绑定驱动的声明式状态，不再依赖一次性遍历可视树；新增真实 DataGrid 翻页回归测试。

### 3.3 问题 3：级别文字改为 INFO/WARN/ERROR

**根因：** `LogTableRow.LevelTextFor` 主动将 `LogSeverity` 映射为“信息/警告/错误”等中文，`LogTableLevelTextStyle` 的颜色触发器也依赖中文值。

**反证：** 底层 `LogSeverity`、JSONL 和查询语法已经使用标准严重级别 token，不需要修改日志格式或解析器。

**修复边界：** 只修改表格投影、颜色触发器和 `LogTableRowTests`；建议完整映射为 `TRACE/DEBUG/INFO/WARN/ERROR/FATAL`。

### 3.4 问题 4：时间排序混乱

**根因：** 当前分页索引按“来源目录顺序＋物理行顺序”生成 ordinal，`NewestFirst` 主要反转 ordinal，并非按 `LogEvent.Timestamp` 做跨来源全局稳定排序。关键位置为 `LogQueryService.BuildPageIndex` 和 `LogQueryService.ReadPage`。

放大因素：

- startup fallback 的目录位置可能与真实事件时间不一致；
- 无法识别时间的兼容行会使用解码时的 `UtcNow`；
- 高优先级队列先于普通队列排空，物理写入顺序不保证等于事件时间顺序。

**反证：** 非分页 `LogTailReader.ReadLatest` 会按 timestamp 排序；结构化 JSONL 的 ISO 时间也可正确解析。因此问题集中在分页查询语义，不是所有日志读取路径都错误。

**测试缺口：** 现有分页夹具让事件时间与物理写入顺序保持一致，没有构造 legacy、startup、JSONL 和归档交错场景。

**修复边界：** 先冻结“排序键 = Timestamp + 稳定 EventId/ordinal tie-breaker”的契约，再设计不破坏大日志分页性能的索引策略；不能在 UI 层对单页结果临时排序，否则跨页仍会错误。

### 3.5 问题 5：时间列箭头样式

**根因：** 表头在 XAML 中永久写死 `↕`；分页协调器虽持有正序/倒序状态，但没有把状态投影回列头图标。

**反证：** 点击排序和服务端方向切换已接通，缺失的是方向可见性，而不是排序按钮完全无效。

**修复边界：** 使用 Fluent/MDL2 方向图标或轻量 chevron，根据当前排序方向显示上/下状态；不要修改查询服务来解决图标问题。

### 3.6 问题 6：筛选弹层与高级条件

**根因：** `logFilterPanel` 是参与页面布局的内联 `Border`，按钮只切换 `Visibility`；当前可视条件只有级别和会话。高级查询字段主要存在于文本查询/`LogFilterBuilder`，没有条件构建 UI。

**反证：** 后端组合查询能力不是空白，已经支持 severity/component/event/op/trace/pid/tid/message/time 等字段；不应再造第二套筛选执行器。

**修复边界：** 文档明确允许延后。实施时将同一 AST 真源承载到 Popup/Flyout，常用条件为级别、来源、状态、类别；更多条件再展开诊断、调用链和触发来源字段。

### 3.7 问题 7：移除“全部会话”

**根因：** `LogSessionPickerItem.AllSessions()` 不只是文案项，它还是默认选择、退出会话视图、恢复主筛选与分页状态的哨兵。

**反证：** 直接删除 ComboBox 或“全部会话”项会破坏 `GetSessionSelectionAction` 和 `RestoreSessionView`，不是纯 XAML 删除。

**修复边界：** 如果主面板不再显示会话，下层仍需保留“无会话过滤”的明确状态；将会话过滤迁入筛选弹层，并提供“清除会话筛选”，再移除主面板控件。

### 3.8 问题 8：当前页高亮

**根因：** `LogPageNumberToken.IsCurrent` 已正确生成，但 `RenderPagerTokens` 只把当前按钮设为 `IsEnabled=false`；所有页共用没有禁用/当前态视觉触发器的 `LogToolbarCompactButton`。

**反证：** 当前页状态和不可重复点击逻辑均存在，缺失的是视觉表达。

**修复边界：** 增加专用页码按钮样式或显式 `IsCurrent` 触发器；测试覆盖“第 N 页→切换页大小→第 1 页高亮”。

### 3.9 问题 9：自定义日期时间选择器

**根因：** `panelLogCustomRange` 使用两个裸 `TextBox`；`SettingsLogSearchCoordinator` 在 `TextChanged` 后静默解析，失败时得到 `null`，没有选择器或明确错误反馈。

**反证：** `LogViewCustomRangeParser` 和时间范围过滤语义已经存在，后端不需要重写。

**修复边界：** 使用项目现有 WPF/Fluent 风格 DatePicker 与时间输入组合，仍向现有过滤管线提供 `DateTime?`；增加起止顺序和无效输入反馈。

### 3.10 问题 10：当前空闲始终 0 秒、状态可能过期

**根因：** 2 秒定时器在分页模式调用 `DetectPagedLogChanges`；日志 fingerprint 未变化时立即返回。空闲秒数仅在 `ApplyPagedStatus` 应用分页结果时重新读取，所以“没有新日志、只有时间流逝”不会更新状态栏。

状态文件超过阈值后，`LogViewIdleReader` 会回落到本机 `GetLastInputInfo`。用户正在操作日志页时该值可以合法为 0，于是可能持续看到“当前空闲 0 秒｜空闲状态可能过期”。

**反证：** `LogViewIdleReader` 已实现外推、90 秒提示和 300 秒淘汰；`73247a5` 也修复了分页计时器启动/恢复以及有新日志时自动刷新。最新测试已经等待真实 `DispatcherTimer`，并覆盖离页返回、`WindowRestored`、`timer.IsEnabled` 和追加日志自动出现；当前缺口仅是“日志 fingerprint 不变时，空闲秒数仍应随 Tick 更新”的真实计时器场景。

**修复边界：** 每个 Tick 只更新轻量状态文字；只有 fingerprint 变化才启动昂贵分页查询。新增日志不变时空闲秒数仍变化的真实计时器测试。

### 3.11 问题 11：插电/拔电事件不显示

**原始根因：** 生产端第一次观察只建立基线，只有后续变化才记录；同时旧分页页面可能没有启动自动刷新，或检测到新快照后只要求手动刷新。

**当前状态：** `73247a5` 已补齐第一页最新优先时的新快照自动查询。当前真实日志中已有 4 条 `PowerSourceChanged`，其中最新拔电和插电事件来自 1.5.4 运行进程。

**反证：** “Engine 不产生插拔电事件”已被代码、测试和真实 JSONL 共同否定。

**剩余验收：** 仍需在日志页打开且位于第一页时实际拔电、插电，确认事件无需点击刷新即可出现。

### 3.12 问题 12：状态列全为“—”

**原始根因：** 修复前没有可信状态字段，投影器不能根据 severity/message 猜测状态，因此固定显示“—”。

**当前状态：** 新电源事件写入 `properties.outcome="handled"`，`LogTableRow.ResolveStatus` 映射为“已处理”；legacy 和未登记 outcome 的结构化事件继续显示“—”。

**反证：** “properties 在序列化/解析中丢失”已被 JSONL round-trip、投影测试和当前真实日志否定。

**仍存在的产品问题：** 当前真实覆盖率仅 `2/341≈0.59%`。因此状态列虽不再技术上“全是 —”，但在普通第一页仍几乎没有信息价值。应在以下两种方案中二选一：

1. 扩展具有明确结果语义的生产者，逐步提高 outcome 覆盖率，并保留“—”作为未知；
2. 在覆盖率达到可用阈值前隐藏状态列或仅在筛选/详情中显示。

禁止根据 INFO/WARN/ERROR 自动推导“成功/警告/失败”，否则会制造错误事实。

### 3.13 问题 13：关于→维护中的诊断详情割裂

**根因：** 诊断详情被放入“关于→维护”，但文案和实现仍依赖“日志页当前筛选条件”。激活诊断区域时会隐式初始化日志页控制器，并从隐藏的日志控件读取筛选状态，导致页面位置与状态所有权不一致。

**反证：** 数据链并未断开；聚合服务、generation 取消和查询表达式仍由同一 `SettingsLogPageHost` 协调。问题是信息架构和状态来源不透明。

**修复边界：** 推荐把诊断统计从维护页移回日志上下文中的按需详情；如果必须留在维护页，应提升为页面无关的显式筛选模型，并清楚显示统计范围。不要复制查询或聚合服务。

## 4. 为什么会集中出现这么多问题

### 4.1 直接原因：连续局部改造没有重新冻结端到端契约

日志页在 2026-08-08 至 2026-08-09 先后经历状态机、分页协调器、表格投影、编号分页、界面精简、诊断迁移、电源轮询和状态字段补丁。短时间内多轮改造分别让局部测试通过，但没有在每轮后重新冻结以下端到端契约：

- 日志的全局排序键是什么；
- UI 状态在翻页、虚拟化、离页、恢复和定时器 Tick 中如何保持；
- 每一列的数据覆盖率达到什么程度才允许常驻；
- 主页面与维护页面各自拥有哪部分筛选/诊断状态；
- 参考图要求是视觉目标还是交互契约。

### 4.2 深层原因一：旧工作台和新编号分页并存

`SettingsLogPageHost` 同时协调旧 `LogViewController`、新 `SettingsLogPaginationCoordinator`、会话、关联、统计和刷新管线。虽然拆成多个 partial 文件，但状态仍集中在同一个宿主，并且部分状态来自控件而不是独立模型。

结果是：

- 自动换行依赖可视树，而不是绑定状态；
- 诊断详情从隐藏日志控件读取筛选；
- 空闲状态刷新被日志 fingerprint 刷新路径绑架；
- 会话的显示项同时承担状态机哨兵职责。

### 4.3 深层原因二：数据模型与表格设计不同步

表格先固定了“状态”列，但生产者没有同步定义 outcome 覆盖策略；分页 UI承诺按时间排序，但索引仍使用物理 ordinal；兼容 legacy 行、startup fallback 和结构化 JSONL 的时间语义没有统一到分页契约。

这会造成“控件存在、测试也绿，但信息不可信或无用”的问题。

### 4.4 深层原因三：测试覆盖实现节点，没有覆盖完整用户生命周期

典型例子：

- 自动换行测试验证勾选当下的行高，没有验证切页后的新单元格；
- 页码测试验证 `IsCurrent` token，没有验证高亮像素；
- 自动刷新测试直接调用刷新方法，没有等待真实计时器；
- 排序夹具让时间与物理顺序天然一致；
- 状态覆盖曾使用仓库根目录的 12 条兼容日志，而不是真实安装日志；
- 进程内窗口矩阵验证分页数字，没有覆盖真实插拔电和长期交互。

因此，测试数量很多与用户问题很多并不矛盾：测试覆盖了大量局部逻辑，却漏掉了跨状态、跨时间、跨来源的组合路径。

### 4.5 深层原因四：执行清单与实际产品方向发生漂移

原执行清单只正式完成到 P1-02，P1-03～P2-05仍标记未开始，P0 真实窗口项目也有明确 NotRun；但之后已经额外实施了会话、统计迁移、编号分页和多轮 UI 改造。计划状态、产品现状和验收矩阵没有同步重基线。

这使“某个 Task 已审查通过”只能说明当时那个切片成立，不能证明后来叠加的页面仍满足完整用户路径。

## 5. 建议修复顺序

### Slice A：先恢复信息真实性

1. 时间排序契约与跨来源分页（问题 4）；
2. 自动换行声明式状态及翻页测试（问题 2）；
3. 空闲状态独立定时刷新（问题 10）。

每项必须先写会失败的真实生命周期测试，再做最小实现。

### Slice B：收敛核心可见体验

1. INFO/WARN/ERROR 投影与颜色（问题 3）；
2. 状态化时间方向图标（问题 5）；
3. 当前页高亮（问题 8）；
4. 日志说明间距（问题 1）；
5. 日期时间选择器与校验（问题 9）。

此批需要真实窗口截图验收，不能只验证 XAML 字符串存在。

### Slice C：重整筛选与会话

1. 将会话迁入筛选并保留明确的“无会话过滤”状态（问题 7）；
